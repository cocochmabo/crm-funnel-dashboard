# Воронка сделок — дашборд CRM для Битрикс24

Приложение показывает аналитику по сделкам CRM портала Битрикс24: сводку по стадиям
воронки, ключевые показатели и последние сделки. Открывается внутри Битрикс24
(пункт меню, вкладка карточки или раздел аналитики) и работает на данных портала.

## Что внутри

| Файл / папка | Назначение |
|---|---|
| `server.js` | HTTP-сервер на `node:http`: статика из `public/`, `/api/dashboard`, `/api/health` |
| `lib/portal.js` | Клиент REST-прокси портала, разметка отказов по `error.code`, загрузка `.env` |
| `lib/dashboard.js` | Фоновые снимки по периодам и воронкам, разбор агрегатов, справочники стадий и сотрудников |
| `public/index.html` | Разметка дашборда |
| `public/styles.css` | Оформление (адаптив, печатная «бумажная» палитра) |
| `public/app.js` | Клиентская логика: фильтры, отрисовка, отчёт высоты во фрейм Битрикс24 |
| `icon.svg` | Иконка карточки приложения в каталоге |
| `vibecode.json` | Название и описание карточки приложения |

## Переменные окружения

Значения в коде не хранятся и в архив не входят — только имена:

- `BITRIX_API_KEY` — ключ приложения для доступа к порталу (заголовок `X-Api-Key`);
- `BITRIX_API_BASE_URL` — базовый адрес REST-прокси портала;
- `BITRIX_PORTAL_DOMAIN` — домен портала для ссылок на карточки сделок;
- `PORT` — порт прослушивания (по умолчанию `3000`);
- `PORTAL_TIMEOUT_MS` — таймаут запросов к порталу (по умолчанию `180000`).

Для локального запуска создайте рядом с `server.js` файл `.env` с этими значениями
(он в `.gitignore` и никогда не должен попадать в репозиторий или архив).

## Запуск

```bash
git clone https://github.com/cocochmabo/crm-funnel-dashboard.git
cd crm-funnel-dashboard
cp .env.example .env     # заполнить BITRIX_API_KEY, BITRIX_API_BASE_URL, BITRIX_PORTAL_DOMAIN
npm start                # или: node server.js
```

Внешних зависимостей нет, `npm install` не требуется. Требуется Node.js 20 или новее.

Без заполненного `.env` приложение тоже стартует: интерфейс открывается, а `/api/*`
отвечает понятным сообщением, что ключ приложения не задан. Для живых данных нужны
все три переменные — их можно задать и окружением, тогда `.env` не нужен.

## Как устроена работа с порталом

- Запросы к порталу делает только сервер: ключ не попадает в браузер, фронт ходит
  исключительно на собственные `/api/*`.
- Портал отвечает десятками секунд, поэтому данные собираются в фоне и отдаются из
  памяти; при сбое показываются прошлые значения с честной подписью «обновлено ЧЧ:ММ».
- Счётчики берутся из `/deals/aggregate` (серверный подсчёт), а не из подсчёта строк
  одной страницы выдачи; признак обрезки агрегата выводится предупреждением.
- Отказы портала размечаются по `error.code` (права, тариф, таймаут, ключ), чтобы
  приложение не давало ложных советов про подключение.

## Встройка в Битрикс24

Место встройки привязывает платформа от имени администратора портала; приложение
читает `placement` и `placement_options` из адреса страницы, не запрещает фрейминг и
сообщает свою высоту через `postMessage` для «Авто-высоты iframe».
